# TOD 审计凭证智能核对

TOD 是一款在 Windows 本机运行的审计细节测试辅助工具。它读取 Excel 底稿中的样本，识别发票、付款单、凭证和合同，核对金额及摘要，并生成可供复核的核对报告。判定为“一致”的样本自动回填底稿，“存疑”和“不一致”的样本保留给审计人员处理。

## 解决什么问题

凭证核对通常需要在底稿与多份支持性材料之间反复切换：找到对应样本，提取单据号，确认含税或不含税金额，核对交易内容，再填写底稿。材料格式和底稿表头不统一时，重复操作会进一步增加。

TOD 将这些步骤串成一个本地流程，通过明确的匹配规则、差异原因和来源文件记录，帮助审计人员更快找到需要关注的样本。

## 主要功能

- **底稿识别**：定位样本序号、金额、摘要及支持性文件列，支持多行表头与手动指定列。
- **材料识别**：读取 PDF 文本层；对扫描件和图片调用本地 PaddleOCR，提取金额、单据号、公司名称及日期。
- **金额核对**：支持单张金额、多张发票求和，以及含税、不含税等金额口径。
- **按需读取合同**：优先核对发票、付款单和凭证，前序金额未匹配时再读取合同，减少无效识别。
- **三态结果**：结合金额匹配、摘要相似度、关键号码和冲突信号，区分一致、存疑与不一致。
- **底稿回填与报告**：仅回填一致样本，输出底稿副本、Excel 报告和 Markdown 报告。
- **桌面与命令行**：提供文件选择、参数设置、后台核对和运行日志，也可通过 CLI 批量调用。

## 快速开始

推荐环境：Windows 10/11、64 位 Python 3.12，默认使用 CPU，无需独立显卡。

1. 尚未安装 Python 3.12 时，先安装 [Python 3.12.10 Windows 64 位版本](https://www.python.org/downloads/release/python-31210/)，安装时保留 Python Launcher，并勾选 **Add python.exe to PATH**。
2. 在 GitHub 点击 **Code → Download ZIP**，将压缩包完整解压到可写目录。
3. 双击 **`启动TOD.bat`**。首次启动会自动创建环境、安装依赖并下载所需 OCR 模型，请保持联网并等待完成。之后双击同一文件即可打开界面。
4. 在界面中选择材料文件夹和 Excel 底稿，检查参数后点击“开始核对”。

首次准备只处理程序依赖和模型，不需要选择业务材料。模型下载完成后可断网使用；离线机器应提前准备好环境和模型。环境文件位于项目的 `.venv/`，OCR 模型由 PaddleOCR 缓存在当前 Windows 用户目录。

### 材料怎么放

每个样本使用独立子目录，目录名以底稿样本序号开头。文件名包含“发票”“付款单”“合同”等类型关键词，有助于正确分类。

```text
材料/
  1/
    发票.pdf
    付款单.pdf
  2/
    发票.png
    合同.pdf
```

底稿使用 `.xlsx` 格式，至少包含样本序号、金额、摘要及支持性文件或证据目标列。自动定位有歧义时，在界面中指定列后再运行。

### 输出结果

默认在底稿所在目录生成：

| 文件 | 用途 |
| --- | --- |
| `底稿_已填.xlsx` | 一致样本的支持性文件编号和匹配结果 |
| `核对报告.xlsx` | 逐样本判定、差异原因、识别金额和来源文件 |
| `核对报告.md` | 便于快速查看的文本报告 |

建议将输入副本放入单独的工作目录，每次运行前确认没有需要保留的同名输出。先查看核对报告，再使用已填底稿。

## 命令行运行

完成首次启动后，在项目目录打开 PowerShell：

```powershell
.\.venv\Scripts\python.exe tod_reconcile.py --help
.\.venv\Scripts\python.exe tod_reconcile.py --input-dir .\local-data\materials --workpaper .\local-data\workpaper.xlsx --offline --soft-summary false
```

`--input-dir` 和 `--workpaper` 为必填参数，路径可替换为自己的本地目录。`--soft-summary false` 关闭摘要软匹配；`--offline` 设置离线相关标志，离线使用仍需提前准备模型。

## 技术架构

```text
Excel 底稿 + 本地材料
         ↓
底稿列定位 → 材料分类 → PDF 文本提取 / 本地 OCR
         ↓
金额匹配 + 摘要相似度 + 号码与冲突检查
         ↓
一致 / 存疑 / 不一致 → 底稿回填 + 核对报告
```

| 模块 | 职责 |
| --- | --- |
| `tod_gui.py` | Tkinter 桌面界面、参数管理和后台任务 |
| `tod_reconcile.py` | CLI 入口和统一流程编排 |
| `core/` | 底稿读写、材料发现、字段解析和核对规则 |
| `engines/` | OCR 后端及同一进程内的引擎复用 |
| `report.py` | Excel 和 Markdown 报告生成 |
| `start.py` | 首次环境准备与桌面启动 |

## 使用说明

- 核对在本机完成，仓库不附带业务材料。输入、输出、本机配置及模型目录默认不进入 Git。
- 本工具辅助整理和核对证据，最终结论应由审计人员复核。低 OCR 置信度、摘要软匹配及金额口径需要结合原材料判断。
- 普通 PDF 材料有读取页数限制；合同复核默认最多读取前 15 页。报告目前提供文件及聚合字段级追溯，不能替代逐页检查。
- 首次安装和模型准备需要联网；应用中的离线选项不替代操作系统的网络隔离。

## 常见问题

**提示找不到 Python 3.12**：安装上方链接中的 64 位版本，勾选 PATH 和 Python Launcher，然后重新双击启动文件。

**首次启动停留在安装或模型下载**：等待当前步骤完成；网络失败时检查连接后重新启动。已经创建的环境会继续使用，无需删除文件。

**无法写入 Excel 输出**：关闭正在打开的输出文件，并确认底稿目录可写。

**需要手动安装**：在项目目录执行以下命令，再运行桌面界面。首次处理扫描件时，OCR 引擎会准备所需模型。

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe tod_gui.py
```
